🧩 Verint CRM Widget: Options Guide

Embed Verint as a full-size page in the Agent Desktop, and choose per team whether a new call pops a record or leaves the agent where they are.

How it works, in 4 steps

Everything is set in the attributes of the verint-iframe entry in your desktop layout, plus a few flow variables.

1
Desktop loads
The widget shows your idleUrl, such as the Verint home page, as soon as the tab is opened.
2
A call arrives
The flow can set popNewCallsOnWidget and the values the Verint page needs.
3
Pop or stay
Pop is true and every required value is set: the record opens. Otherwise the agent stays on their open page.
4
Call ends
The page is left alone. The agent carries on with whatever is on screen.

The options at a glance

Four choices cover almost every team.

popNewCallsOnWidget

A flow variable. true (also 1 or yes) opens the Verint create page for the new call. Anything else, or not set, ignores the call so the agent can take a call and come back to their work.

keepAlive on or off

On by default. The page keeps its place when the agent clicks to another tab and back. "false" reloads it each time the tab is opened.

idleUrl first page

What the tab shows before any call has been popped. It is shown once, and is not reloaded when a call ends.

callType and muniValue

When the call type matches muniValue (default MUNI, not case sensitive), the pop leaves out the phone number and the context value.

Pick the behavior for each team

Set the flow variable per queue or entry point. The layout stays the same.

💡 Missing values? If pop is true but a required value is not set yet, the widget waits for it and opens the page as soon as it arrives. If it never arrives, the agent simply stays on the current page.

What gets opened

The pop builds the URL from your baseUrl and the flow variables.

Call type matches muniValue

{baseUrl}?channel=…&source_id=…&external_ref=…

Any other call type

{baseUrl}?channel=…&context=reporter&phone=…&source_id=…&external_ref=…

The Desktop passes attribute names in lowercase. The widget handles that for you.

Put it all together

Add this to the navigation list of the agent, supervisor and supervisorAgent personas. Pin the version in the script address so a later release never changes your desktop unexpectedly.

// replace YOUR-VERINT-HOST and the icon address
{
  "nav": { "label": "Verint CRM", "icon": "https://example.com/verint-icon.png",
          "iconType": "other", "navigateTo": "verint-crm", "align": "top" },
  "page": {
    "id": "verint-crm",
    "widgets": { "left": {
      "comp": "verint-iframe",
      "script": "https://cdn.jsdelivr.net/gh/jbaumerdemos/verint-embedded-crm@v1.0.3/verintHandler.js",
      "attributes": {
        "baseUrl": "https://YOUR-VERINT-HOST/interactions/create",
        "idleUrl": "https://YOUR-VERINT-HOST/",
        "popNewCallsOnWidget": "$STORE.agentContact.taskSelected.callAssociatedData.popNewCallsOnWidget.value",
        "keepAlive": "true",
        "muniValue": "MUNI",
        "callType": "$STORE.agentContact.taskSelected.callAssociatedData.CallType.value",
        "channelKey": "$STORE.agentContact.taskSelected.callAssociatedData.Channel_Key.value",
        "flexibleId": "$STORE.agentContact.taskSelected.callAssociatedData.Flexible_Id.value",
        "ciscoCallId": "$STORE.agentContact.taskSelected.callAssociatedData.Cisco_Call_Id.value",
        "customerPhone": "$STORE.agentContact.taskSelected.callAssociatedData.Customer_Phone.value"
      }
    } },
    "layout": { "areas": [["left"]], "size": { "cols": [1], "rows": [1] } }
  }
}

Optional: alert when the caller hangs up

A separate widget that shows a desktop notification when a contact ends while the browser is minimized or in the background. Add it to the layout's headless area.

"call-ended-notifier": {
  "comp": "call-ended-notifier",
  "script": "https://cdn.jsdelivr.net/gh/jbaumerdemos/wxcc-desktop-widgets@v1.0.3/dist/call-ended-notifier.js",
  "attributes": { "title": "Caller disconnected", "onlyHidden": "true" }
}

onlyHidden

true (default) shows the notification only when the Desktop is hidden or not in focus. false always shows it.

Notifications

The browser must allow notifications for the Desktop's address. Clicking the notification brings the Desktop back to the front. Windows Focus Assist can hide it.

Things to know

Sign-in framing

The Verint site, and the single sign-on page it redirects to, must allow being shown inside the Desktop. If not, agents see a blank page or "refused to connect". Your IT team can allow your Desktop address as a permitted frame ancestor, and set the session cookies to SameSite=None; Secure.

Memory keep-alive in VDI

With keep-alive on, the hidden page keeps running so the agent returns to where they were. In a virtual desktop it uses a little more memory. Turn it off for teams that do not need it. If the Desktop ever stops the kept page from lining up with the tab, the widget falls back to a normal embedded page on its own, so agents never see a blank area.

Updates versions

The script address ends in a version (@v1.0.3). Update the layout when you want a newer release, and test it first. Existing versions never change.

Settle time

The widget waits about a third of a second when a call arrives, so that all the values update together before it decides.

If something looks wrong

Open the browser console (F12) and filter on verint-iframe. The widget logs each decision.

Console messageMeaning
loading <url>The widget opened that page. If the page is blank, the Verint site is refusing to be framed.
call ignored: popNewCallsOnWidget is not trueWorking as designed. The agent stays on the open page.
waiting for variables: …Pop is on, but those values are not set yet. Check the flow sets them and marks them Agent Viewable.
render { callId, rawCallId, pop, keepAlive }What the widget saw for the current call. An empty callId means no call id was received.
Nothing logged at allThe script did not load. Check the script address in the Network tab, and that comp is verint-iframe.

Quick tips

✅ Test with the flow variable set to true and to false on the same agent, so the team sees both behaviors.
🔁 After changing the script address or the layout, upload the layout and hard-refresh the Desktop (Ctrl+F5).
🧪 The same call never opens twice. To re-test a pop, use a new call.
